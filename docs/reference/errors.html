Error Reference

Every failure Owl-E reports carries a stable code, a message stating the rule in general terms, and a detail naming the specific value that broke it. Codes are the contract: they are safe to branch on and will not change wording underneath you.

TYPE_INVALID_DECIMAL_SCALE DecimalScaleExceeded

Value must fit the fixed precision and scale of its column.

Fails if the value carries more than [maxScale] digits after the decimal point, or more than [maxPrecision] significant digits overall — the two facts a DB `DECIMAL(precision, scale)` column enforces natively and a Kotlin `Double` does not. Comparing against a `DECIMAL` type's own semantics (not float rounding) means going through [java.math.BigDecimal].

Not raised by any annotated field.

TYPE_INVALID_HEX_COLOR HexColorFormat

Value must be a hexadecimal colour in full six-digit form, such as #1E88E5.

Fails unless the value is a full-form CSS hex colour: `#` followed by exactly six hex digits, either case. Null passes - the column is nullable and "no colour set" is a legitimate state. The short form (`#abc`) is deliberately rejected rather than expanded: the column is `varchar(7)`, and accepting two spellings of the same colour would mean every comparison and every round-trip has to normalise first.
